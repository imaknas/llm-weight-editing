# 計畫:IWIBench 混合修改檔的成分拆解

狀態:草案,尚未執行。先經獨立審查再定案。

## 1. 要回答的問題

IWIBench 公開的 330 個回合(family 0.2.2)裡,最終修改檔同時改了「詞向量矩陣」與「內部層參數」而且有得分的只有四個。
**在這四個修改檔裡,內部層的那一部分對得分有沒有貢獻?**

背景:公開資料顯示,有得分的回合幾乎都只改詞向量矩陣;只改內部層的修改檔沒有一個得分。這四個是僅有的、內部層修改
可能起了作用的例子,但沒有人把它們拆開檢查過(IWIBench 論文沒有提到內部層;三個獨立的文獻搜尋也沒找到)。

這個實驗不需要編輯模型,只需要執行被修改的模型(Gemma 3 4B)。它不回答「放寬工具後編輯者能否改動內部層」。

## 2. 對象

| 代號 | trace id | 編輯者 | 任務(種子) | 公布的結果 | 修改檔裡的張量 |
|---|---|---|---|---|---|
| F | e96400198e… | gpt-5.6-terra (low) | factual_update (0) | 目標 0 → 1 / 3;對照 62 / 67;reward 0.308 | 詞向量 + 第 33 層 MLP 的 down / gate / up |
| W-hi | 36209ad6… | gpt-6.1-sol (high) | selective_factual_withholding (0) | 目標 0 → 3 / 3;對照 70 / 70;reward 1.0 | 詞向量 + 第 30–33 層 MLP 的 gate / up |
| W-med | 266ed91f… | gpt-6.1-sol (medium) | selective_factual_withholding (0) | 目標 0 → 3 / 3;對照 70 / 70;reward 1.0 | 詞向量 + 第 0–1 層 MLP 的 gate / up |
| S | 7784325c… | gpt-6.1-sol (medium) | resistance_to_false_suggestions (2) | 目標 34 → 47 / 64;對照 110 / 110;reward 0.433 | 詞向量 + 第 23、29 層的 post-attention layernorm |

- 四個修改檔都是稀疏格式(逐張量的「位置 + 新值」),張量名稱在檔內,不需要推斷。
- W-hi 與 W-med 是同一題(同一個種子),由同一個編輯模型在不同推理力度下各自做出。
- 題目由 `iwibench.families.episode(family, seed, "development", model)` 從種子決定性地產生。已確認四個回合重建出的
  episode id、probe seed、test seed 與公開索引逐一相同。

## 3. 條件

對每個修改檔,用 IWIBench 自己的評分流程(全新程序載入原始 checkpoint → 套用修改檔 → 對同一批題目貪婪解碼 →
`score_episode`)評估下列版本:

| 條件 | 套用的內容 |
|---|---|
| base | 不套用任何修改 |
| full | 公布的修改檔原樣 |
| emb | 只保留詞向量矩陣那一項 |
| int | 只保留內部層的各項 |

補充條件(探索性,只在主要結果需要時解讀):
- **逐層**:W-hi、W-med、S 的內部層部分逐層或逐張量類型單獨保留 / 單獨拿掉。
- **輸入端 / 輸出端**:Gemma 的輸入詞表與輸出層共用同一個矩陣。把兩者解開,讓詞向量那一項只作用在輸入端或只作用在輸出端,
  看詞向量的修改是在哪一端起作用。這一項需要改動載入後的模型(複製出獨立的輸出層權重),不屬於 IWIBench 原本的評分流程。

拆解的做法:讀原始的 safetensors 修改檔,依張量名稱選出子集,寫成同樣格式的新檔(同樣的 metadata,只是 sparse 清單變短),
用同一個 `NativeTarget.apply_patch` 套用。base 與 full 不經過這個改寫步驟。

## 4. 評分

- **主要指標**:IWIBench 的 reward = max(0, (e − b) / (1 − b)) × 對照保留率,以及它的兩個組成(目標成功數、保留的對照數)。
- 對照題:除了原本那一組 general controls(64 題),另外用 `replay_patch.py` 的做法換 4 個新的 control seed,
  每個條件多 256 題對照,用來看保留率的差異。目標題不變。
- 解碼是貪婪的,同一台機器上重複執行應該得到相同輸出;實際重跑一次 base 確認。
- 每一題的原始輸出都存檔。

## 5. 先決條件:在這台機器上重現公布的數字

IWIBench 的結果是在 CUDA 上以 BF16 算的;這裡是 Apple MPS。數值上的些微差異可能讓貪婪解碼在某些題目上走不同的路。

- **閘門**:四個修改檔的 base 與 full,在這台機器上算出的「目標成功數」與「保留的對照數」要與公布的數字相同
  (上表)。
- 若 MPS 對不上,改用 CPU(float32 或 BF16)再試,並報告哪一種設定對得上。
- 若沒有任何設定能完全重現:報告逐條件的差距;只有在 base 與 full 的 reward 與公布值相差不超過 0.05 時才繼續,
  而且所有結論都以這台機器自己的 base / full 為比較基準,並註明與公布值的差距。
- 對程式的唯一改動:把寫死的 `device="cuda"` 改成可設定。不改解碼、tokenizer、chat template、評分。

## 6. 事先講好的解讀

以 reward 為準,並同時看目標成功數與對照保留數。「相同」指目標成功數與原 64 題對照的保留數都與 full 相同。

| 結果 | 解讀 |
|---|---|
| emb 與 full 相同 | 內部層的部分對這個修改檔的得分沒有可見的貢獻 |
| emb 的目標成功數低於 full,int 高於 base | 內部層的部分有獨立的貢獻 |
| emb 低於 full,int 與 base 相同 | 內部層的部分只有搭配詞向量的修改才起作用(交互作用) |
| emb 的目標成功數等於 full,但對照保留數不同 | 內部層的部分影響的是副作用,不是目標行為 |
| emb 高於 full | 內部層的部分是有害的 |
| int 讓對照大量失敗 | 內部層的修改單獨存在時會破壞模型;「int 沒有貢獻」不能從這個條件判斷 |

四個修改檔各自報告,不合併成一個結論。樣本很小:F 與兩個 W 各只有 3 個目標題,任何差異都只是「這一個修改檔」的事實。

## 7. 不會宣稱的事

- 不宣稱「內部層的修改一般而言有用 / 沒用」:只有四個修改檔、三個任務、兩個編輯模型。
- 不宣稱編輯者「知道」自己在做什麼:這裡只看修改的效果,不看過程。
- 不把這台機器上的數字當成 IWIBench 的官方數字。

## 8. 產出

- `analysis/` 下的腳本:拆解修改檔、執行評分、彙整表格;每一步可重跑。
- 每個條件每一題的輸出與評分(放在不進版控的 `data/`),以及一份彙整表(進版控)。
- 結論在採用前交給獨立的一方從原始輸出重算。

## 9. 已知的限制

- Gemma 的權重與由它衍生的修改檔受 Gemma 的授權條款約束;修改檔與模型都不進版控、不對外散布。
- 「只保留詞向量那一項」不等於「編輯者如果只改詞向量會做出的修改」;它只回答這個成品裡各部分的作用。
- 新增的對照題與原本的對照題來自同一個產生器,涵蓋的能力範圍相同(算術、事實、複製)。
