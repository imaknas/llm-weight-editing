# 設計:LLM 讀/改神經網路權重的擴展實驗

## 目標
以 MIT〈Sparks of Weight-Space Programming〉(LLM 直接讀、改神經網路權重)的想法與做法為起點往外擴展,
重點放在原文沒做或自承做不好的地方,不是複現原文的數字。目前的主軸:

**分散式缺陷的可修性。** 原文說錯誤若分散在網路各處就難修,但沒有量化。這裡把「分散程度」做成旋鈕,
量 LLM 的修復效果怎麼隨之變化,並跟不靠 LLM 的修法比。

小規模的「讀」「改」兩個實驗是打底:確認流程、對照組與量測方式可行。

## 目前進度
- 「讀」實驗已就緒:`wse/read_exp.py`,對照組如下表。純標準庫,訓練約 6 秒。
- 「改」實驗已寫好(`wse/edit_exp.py`),尚未用 LLM 跑過。

| kind | 內容 | 期望答案 | 意義 |
|---|---|---|---|
| trained | 訓練好的網路 | 真正的任務 | 基本能力 |
| permuted | 隱藏單元重排(函數完全相同) | 真正的任務 | 排除「記住特定數字排列」,測是否真讀懂結構 |
| shuffled | 權重值整批打亂 | none | 函數被破壞,數值分佈相同;若仍答任務 = 靠脈絡猜 |
| random | 沒訓練,偏置也隨機 | none | 權重幅度仍明顯偏小,只能當寬鬆對照 |
| randlabel | 同樣流程訓練在隨機標籤上 | none | 權重像訓練過但不對應任何規則;none 類中最嚴格 |

若只有 trained/permuted 高、shuffled/random/randlabel 也答對 none,才算有讀到權重內容的證據。
none 類對照不能留表面破綻:最初的 random 偏置全為 0,LLM 靠這點就能認出來,那一輪的 random 結果不算數。
另外要記得有 4+1 個選項,隨機猜的基準約 20%。

## 結構
- `wse/mlp.py` 純 Python MLP(訓練、排列、打亂、序列化、轉文字)
- `wse/tasks.py` 四個 2D 分類任務
- `wse/llm.py` `LLM` 協定;`BrunnaCompleteLLM`(正式)、`ScriptedLLM`(測試)
- `wse/read_exp.py` 案例產生、prompt、評分;CLI 入口 `main()` 是唯一組裝具體 LLM 的地方
- `wse/defects.py` 缺陷區與缺陷網路的產生;訓練後端以參數傳入
- `wse/torch_train.py` torch 訓練後端(只有 scatter_exp 的入口會載入)
- `tests/` 單元測試(`python3 -m unittest discover -s tests -t .`,不需要 torch)

## 與 MIT 原實驗的差異(要誠實講)
- 打底實驗的網路約 205 個權重(2-12-12-1);原文以文字給權重的網路是 1.7 萬到 17 萬。
- 原文的「讀」沒有對照組;這裡有 permuted / shuffled / random / randlabel。
- 任務是 2D 分類,不是遊戲策略;好處是函數可精確驗證。
- 每種任務只有 2 個種子,樣本很小,第一輪只能當 smoke test,不能下統計結論。

## 打底實驗的結果(樣本都很小)
- 讀:trained 8/8、permuted 8/8;none 類 shuffled 6/8、random 3/4、randlabel 4/4,三筆錯都答 xor。
  none 多半是靠「輸出擠在 0.5 附近、輸出層權重很小」認出來的,這組對照還不夠嚴格。
- 改(205 個權重、一個象限的缺陷):LLM 在 3 個網路、查詢預算 0 與 10 下都把缺陷象限修到 1.00,
  平均改 2–3 個權重;同數量的隨機修改幾乎無效。不查詢也修得好。
- LLM 常在回答裡手算前向傳播;網路這麼小時「讀」與「算」分不開。

## 分散式缺陷實驗(`wse/scatter_exp.py`)
- **旋鈕**:錯誤區固定佔輸入空間 25%,拆成 k 個不共邊的方塊(k = 1、4、9、16)。
  比的是「同樣多的錯,散得多開」。這是輸入空間的分散;它在權重裡散得多開還沒有可靠的量法。
- **正確函數沒有公式**:幾個隨機正弦波相加取正負號(`tasks.wavy_task`),邊界是彎的,而且篩掉能用一條直線
  近似的。LLM 只能靠查詢得知某個點該是哪一類,沒辦法照規則重寫一個網路。
- **改動幅度有上限**:新值不得超出該層原有參數的最大絕對值,超出的截到上限並記數。
- **網路**:2-64-64-1(4,417 個權重),用 torch 訓練。205 個權重的小網路做不出 4 塊以上的缺陷。
- **做法**:no_edit、llm(查詢 100 與 400 個點,回傳網路輸出與正確類別)、random_edit(同數量同上限,
  20 次平均)、query_ft(只用 LLM 查到的點做梯度微調,資訊量相同)、dense_ft(大量正確資料微調,上限)。
- **prompt 不透露缺陷的位置與塊數**,各 k 用同一段說明。
- **已知弱點**:各網路的上限不同(第 1 層 5 到 55),是混入的變因;每個 k 只有 2 個網路;
  查詢預算與 k 的關係只取了兩個點。

### 第一版的試跑(規則 x+y>0、不限改動幅度;k=1 與 k=16 各一個網路)
| k | 查詢 | 缺陷區 | 其餘 | 改動數 | 最大改動值 |
|---|---|---|---|---|---|
| 1 | 0 | 0.01 → 0.62 | 0.99 | 10 | 0(把單元歸零) |
| 1 | 400 | 0.01 → 1.00 | 1.00 | 3 | 10000 |
| 16 | 0 | 0.11 → 0.34 | 0.91 | 1 | 15.5 |
| 16 | 400 | 0.11 → 1.00 | 1.00 | 6 | 1000 |

- **有查詢時 LLM 不是在修,是在覆寫**:它挑一個幾乎沒作用的單元,改成 sign(x+y) 偵測器,再用 200–10000 的
  權重壓過網路其餘部分。LLM 自己也寫明這是繞道、不是最小修正。所以 k 再大結果都會是 1.00,這條曲線沒有意義。
- **沒查詢時才看得到分散度的影響**(0.62 對 0.34),但各只有一個網路。
- 單次修改的花費 US$0.26–1.60,四組共 US$3.68;完整掃一輪(4 個 k × 2 個種子 × 2 種預算)估 US$15–25。
- 這就是現行版本改用無公式目標函數並限制改動幅度的原因。資料留在 `data/pilot_diagonal/`。


## 前人工作與 IWIBench 公開資料的分析(2026-11-15)
- **已有人做的**:局部缺陷用少數權重修好(arXiv 2611.05341,小型臨床決策網路,中位數 3 個參數);
  編輯模型強度的比較(IWIBench,arXiv 2611.08647:10 個模型改 Gemma 3 4B,得分隨模型世代分層)。
  這兩件不再自己重做。
- **IWIBench 當實驗設備的障礙**:寫死 CUDA 與 BF16;Gemma 3 需要授權 token;編輯者要 OpenAI 相容的
  多輪工具呼叫端點。
- **對它公開的 330 個回合做的分析**(`analysis/iwibench_rollouts.py`,只用工具呼叫紀錄與 patch 中繼資料;
  另有一份在看不到前者與其結論下獨立寫成的 `analysis/iwibench_rollouts_blind.py`,同家族模型,數字逐項相符):
  - 3,683 次成功寫入中 3,342 次(91%)落在詞向量 / 輸出矩陣;248 個回合只改這個矩陣。
  - 「回合中寫過」的口徑:36 個回合動過內部層(attention、MLP、norm),其中 30 個得 0 分、6 個有分;
    只動內部層的 16 個回合全部 0 分。
  - 「最終提交的 patch 裡有」的口徑(修改可能被還原):28 個回合含內部層,其中 24 個 0 分、4 個有分;
    只含內部層的 11 個全部 0 分。兩個原本算有分的回合,內部層的寫入其實被還原了,分數來自純詞向量的 patch。
  - 有分的 4 個都同時改了詞向量,無法歸因於內部層:gpt-5.6-terra 的 factual_update(0.31,第 33 層 MLP)、
    gpt-6.1-sol high 與 medium 的 selective_factual_withholding(各 1.00,MLP 第 30–33 層與第 0–1 層)、
    gpt-6.1-sol medium 的 resistance_to_false_suggestions(0.43,第 23、29 層的 norm)。
  - 需要跨情境改變行為的任務(回答長度、預設 JSON)最常嘗試內部層(長度 10/33 回合),也幾乎全數失敗。
  - 限制:每個任務類只有 3 個題目、全部編輯者共用,所以內部層那組很小且集中在少數編輯者與任務,
    和「只改詞向量」那組的得分差不能當因果讀;patch 裡整塊取代的張量在中繼資料裡沒有名字,
    那 8 個 patch 的內容是用排除法推的;`ok` 的寫入不代表有淨改動(7 個回合寫了又還原成沒改)。
- **解讀**:目前「LLM 改語言模型」的成功案例幾乎都是改詞表那一層(某個 token 的列),等於在輸入或輸出端
  調整單一詞的表示;改動內部運算的幾乎沒有成功過。這可能反映工具限制(不能跑程式、只能檢查 4 次內部數值),
  不一定是模型能力的上限。原文修 Qwen 的那次是改內部 MLP,但用的是 Python 環境。
- **因此真正的空白**是「在內部層做可驗證的修改」,以及它如何隨改動的分散程度變化。

## 核心問題的重新定位與相關研究(2026-11-15)
**要問的事**:通用語言模型能不能把「權重」當成自己能直接讀寫的一種型態(編碼進模型內部的表示,不是寫成十進位
文字),並直接對應到行為:看權重 → 預測行為;想要的行為 → 產生或修改權重。對錯由實際執行模型判定,
不要求能用人類語言解釋。把權重寫成文字貼進 prompt(Weight-Space Programming 的做法)相當於把圖片的像素值
寫成文字給模型讀。

以下由子代理讀原文整理,未逐字核對;標「未讀原文」者只有二手資訊。

**讀:權重 → 模型內部 → 輸出**
- Weight Oracles(Oxford,arXiv 2610.07334,NeurIPS 2026 workshop):權重矩陣的每一列投影成 Qwen 2.5 3B 的
  一個輸入向量。目標網路只有約 2K 參數的玩具 transformer。
  - 預測目標網路輸出:99.0%,但要拆成每次前向 5 次 LLM 呼叫、非線性由外部程式算。
  - 一次到位的版本卡在 45%,與「完全不看權重」的分類器 45.1% 相同:模型走了捷徑,沒有用權重。
  - 只用良性異常訓練,偵測沒看過的後門:AUROC 0.93(單一威脅)/ 0.81(四種威脅);L2 範數基準 0.445。
  - 沒比的基準:權重寫成文字、非 LLM 的權重模型、直接執行網路。作者自述放大是主要的未解問題,
    幾百萬參數以上直接注入就不可行。沒有處理單元排列的對稱性。
- Diff Interpretation Tuning(MIT,arXiv 2510.05092,ICLR 2026 camera-ready):沒有編碼器;把權重差直接套在
  模型自己身上,再訓練一個 rank-16 的 adapter 讓它用語言說出自己被改了什麼。目標是真的語言模型(到 Qwen3-8B)。
  - 說出隱藏主題:4.76/5(黑箱提問基準 1.21–1.38)。
  - 跨行為類型幾乎不能遷移(約 1.1–1.25);反推觸發詞 0/100;作用在權重還是 activation,作者說未定。
  - 輸出是語言標籤,沒有做行為預測。

**寫:需求 → 權重**(都以實際執行下游任務評估)
- Text-to-LoRA(Sakana,arXiv 2506.06105):文字任務描述 → LoRA。零樣本 67.7,多任務 LoRA 66.3,
  達不到各任務專屬 LoRA。產生器是另外的 hypernetwork,文字由另一個編碼器處理。
- Infinite-Parameter LLMs(arXiv 2609.18842):文件 → rank-8 LoRA(Qwen3-8B)。多跳問答上勝過把文件放進
  context(HotpotQA 60.4 對 58.7),SQuAD 上輸很多(51.8 對 85.3)。
- 立場論文〈Weight Space Should Be a First-Class Generative AI Modality〉(arXiv 2605.18632):主張權重是
  一級的資料型態;現況是 adapter 規模與條件式生成進展快,整個 checkpoint 的生成仍未解。
- 未讀原文:Doc-to-LoRA、SHINE(重用凍結的主幹當編碼器)、HY-WU、NeuroGen(微調 LLM 直接輸出參數)。

**在讀到的範圍內沒看到的**
1. 同一個模型既讀又寫,或「讀權重 → 決定修改 → 執行驗證」的閉環。
2. 以語言模型為對象的行為預測(DIT 的對象是語言模型,但輸出是語言描述)。
3. 針對既有模型的特定缺陷產生修改(寫的一側都是從任務描述或文件生成 adapter)。
4. 讀完整權重(讀的一側停在 2K 參數;寫的一側停在低秩 adapter)。
5. 讀的一側與「權重寫成文字」「非 LLM 的權重模型」「直接執行」的對照。

**對核心問題最重要的一個證據**:Weight Oracles 的 45% 現象。即使給了原生的權重輸入並專門訓練,3B 的模型
一次前向也沒有學會用權重算出行為,而是忽略權重走捷徑;拆成逐步計算才做得到。這不支持「模型對權重有直覺式
的理解」,比較支持「它能被訓練成一步一步執行權重所代表的計算」。

**這個方向的現實條件**:上述研究都要訓練(微調 3B–8B 的模型、成千上萬個目標模型),需要 GPU;
目前這個專案的環境做不到。

## 閉環方向的既有研究(2026-11-15,動手前的確認)
由子代理讀原文整理,未逐字核對;B、C 兩篇後半是摘要式讀取。

**用通用 LLM(權重以文字或程式工具呈現)做的閉環,已經很多**
- Exploring WSP(上海 AI Lab 等,arXiv 2611.09382):Astra 有 Python 環境,每次搜尋 50 次前向,改 Qwen3.5-0.8B 與 9B
  的內部層(限定不准改詞表)。0.8B:MATH-500 8.35 → 37.80(只改 1,023 個值)、IFEval 21.40 → 58.12;9B 幾乎沒有
  提升,16 條軌跡有 6 條保留原權重。同一題三次搜尋的成果是 +29.45 / +5.00 / +27.30。沒有任何梯度或搜尋基準。
- Computation, not weight access(天津醫大,arXiv 2611.07847):小型 tanh MLP(105–38,401 權重)。
  **黑箱(只能呼叫預測函數)與白箱(看得到權重)結果相同**:讀取的 R² 都是 0.92–0.98,稽核都是 3/3。
  有函數不變的單元重排對照、5 個編輯模型、以及修復時與梯度微調的比較(微調改 207/209 個參數,
  腳本閘門 29 個,Astra 約 16 個)。
- Distilling Instructions into Weights(arXiv 2611.11894):對 3.35B 的機器人策略模型做閉式低秩修改,
  閉環成功率 27/128 → 106/128;同範數的隨機方向對照 9/64(未改 13/64);有保留率檢查。
- Compiling Known Rules(arXiv 2611.16981):LLM 直接寫 57k 參數策略網路的權重,最多三次回饋重寫,
  未見過的關卡 56%;同架構用梯度學的最多 11%(資訊量相同,計算量沒對齊)。
- WeightLoop(arXiv 2611.07319):LLM 只寫一次「有上限的修改程式」,之後隨新量測自動更新 128 個輸出權重。
- 一篇個人部落格:108k 參數 CNN,改 35 個權重修好一個類別且不傷其他類;微調整體最好但每次都讓某個
  相近類別掉 13–26 點。

**訓練出來的權重編輯器(權重以數值直接輸入)**
- GradMetaNet(arXiv 2507.01649)等:輸入「權重 + 梯度(+ 探測輸出)」,一次輸出 Δθ,用在編輯隱式影像表示;
  沒有回饋迴圈,讀到的部分沒有與梯度下降比。

**在讀到的範圍內沒看到的**
1. 訓練出來的(原生權重輸入的)編輯器放進有執行回饋的閉環。
2. 任何編輯器與梯度 / 搜尋方法在「相同執行次數」下、隨回饋預算變化的比較曲線。
3. 對原生權重輸入的編輯器做「有權重 / 只有行為 / 權重被打亂」的對照。文字版的 LLM 已有人做(黑箱 = 白箱),
   原生輸入版沒有。
4. 把缺陷的分散程度或網路大小當成受控變因來掃。

**玩具閉環要回答的問題因此定為**:在相同的執行次數下,「看得到權重」比「只看得到行為」多修好多少,
這個差距怎麼隨回饋預算與缺陷分散度變化。差距為零就表示權重沒有提供行為以外的資訊。

## 獨立重算:Claude 讀真實語言模型的權重能否預測修改的效果(2026-11-15)
資料:公開專案 csinva/weight-space-programming-autoresearch 的 `experiments/systematic-tests/`(作者 Chandan Singh;
commit f012b955)。預測者只能讀檔、不能跑程式;「不讀」只看到修改的描述,「讀權重」另外讀到被改部位的權重數字。
對象是 Qwen3.5-0.8B,8 個句子。腳本:`analysis/singh_weight_reading.py`,只讀原始的真值與預測檔,
沒有使用作者的分析程式。實驗 2、3 沒有重算。

**Opus 5.5,零樣本,300 個修改 × 8 個句子**(我算的 / 報告寫的)

| 類型 | ρ 不讀 | ρ 讀權重 | 差 ± 標準誤 | 報告的差 | MAE 不讀 / 讀 / 永遠猜 0 |
|---|---|---|---|---|---|
| 單一數值(120) | −0.091 | +0.040 | +0.131 ± 0.034 | +0.13 ± 0.04 | 0.339 / 0.403 / 0.294 |
| 神經元(120) | +0.010 | +0.029 | +0.018 ± 0.024 | — | 0.032 / 0.049 / 0.003 |
| 層(60) | +0.119 | +0.190 | +0.071 ± 0.027 | +0.07 ± 0.03 | 0.724 / 0.779 / 0.582 |
| 全部(300) | +0.111 | +0.168 | +0.057 ± 0.016 | +0.06 ± 0.02 | 0.293 / 0.337 / 0.235 |

- 大效應的辨識(單一數值):AUC 0.49 → 0.72,與報告相同。
- 方向正確率(單一數值、|真值| > 1):不讀 0.30、讀權重 0.93,與報告相同;但只有 30 個項目,來自 17 個修改。
- 每一類「永遠猜 0」的誤差都比兩種條件低,與報告相同。讀權重的 MAE 在每一類都比不讀更差。
