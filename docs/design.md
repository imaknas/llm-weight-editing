# 設計:LLM 讀/改神經網路權重的擴展實驗

## 目標
以 MIT〈Sparks of Weight-Space Programming〉(LLM 直接讀、改神經網路權重)的想法與做法為起點往外擴展,
重點放在原文沒做或自承做不好的地方,不是複現原文的數字。目前的主軸:

**分散式缺陷的可修性。** 原文說錯誤若分散在網路各處就難修,但沒有量化。這裡把「分散程度」做成旋鈕,
量 LLM 的修復效果怎麼隨之變化,並跟不靠 LLM 的修法比。

小規模的「讀」「改」兩個實驗是打底:確認流程、對照組與量測方式可行。

## 目前進度
- 「讀」實驗已就緒:`wse/read_exp.py`,對照組如下表。純標準庫,訓練約 6 秒。
- 「改」實驗已寫好(`wse/edit_exp.py`),尚未用 LLM 跑過。

| kind | 內容 | 期望答案 | 意義 |
|---|---|---|---|
| trained | 訓練好的網路 | 真正的任務 | 基本能力 |
| permuted | 隱藏單元重排(函數完全相同) | 真正的任務 | 排除「記住特定數字排列」,測是否真讀懂結構 |
| shuffled | 權重值整批打亂 | none | 函數被破壞,數值分佈相同;若仍答任務 = 靠脈絡猜 |
| random | 沒訓練,偏置也隨機 | none | 權重幅度仍明顯偏小,只能當寬鬆對照 |
| randlabel | 同樣流程訓練在隨機標籤上 | none | 權重像訓練過但不對應任何規則;none 類中最嚴格 |

若只有 trained/permuted 高、shuffled/random/randlabel 也答對 none,才算有讀到權重內容的證據。
none 類對照不能留表面破綻:最初的 random 偏置全為 0,LLM 靠這點就能認出來,那一輪的 random 結果不算數。
另外要記得有 4+1 個選項,隨機猜的基準約 20%。

## 結構
- `wse/mlp.py` 純 Python MLP(訓練、排列、打亂、序列化、轉文字)
- `wse/tasks.py` 四個 2D 分類任務
- `wse/llm.py` `LLM` 協定;`BrunnaCompleteLLM`(正式)、`ScriptedLLM`(測試)
- `wse/read_exp.py` 案例產生、prompt、評分;CLI 入口 `main()` 是唯一組裝具體 LLM 的地方
- `wse/defects.py` 缺陷區與缺陷網路的產生;訓練後端以參數傳入
- `wse/torch_train.py` torch 訓練後端(只有 scatter_exp 的入口會載入)
- `tests/` 單元測試(`python3 -m unittest discover -s tests -t .`,不需要 torch)

## 與 MIT 原實驗的差異(要誠實講)
- 打底實驗的網路約 205 個權重(2-12-12-1);原文以文字給權重的網路是 1.7 萬到 17 萬。
- 原文的「讀」沒有對照組;這裡有 permuted / shuffled / random / randlabel。
- 任務是 2D 分類,不是遊戲策略;好處是函數可精確驗證。
- 每種任務只有 2 個種子,樣本很小,第一輪只能當 smoke test,不能下統計結論。

## 打底實驗的結果(樣本都很小)
- 讀:trained 8/8、permuted 8/8;none 類 shuffled 6/8、random 3/4、randlabel 4/4,三筆錯都答 xor。
  none 多半是靠「輸出擠在 0.5 附近、輸出層權重很小」認出來的,這組對照還不夠嚴格。
- 改(205 個權重、一個象限的缺陷):LLM 在 3 個網路、查詢預算 0 與 10 下都把缺陷象限修到 1.00,
  平均改 2–3 個權重;同數量的隨機修改幾乎無效。不查詢也修得好。
- LLM 常在回答裡手算前向傳播;網路這麼小時「讀」與「算」分不開。

## 分散式缺陷實驗(`wse/scatter_exp.py`)
- **旋鈕**:錯誤區固定佔輸入空間 25%,拆成 k 個不共邊的方塊(k = 1、4、9、16;k=1 就是一個象限)。
  比的是「同樣多的錯,散得多開」。這是輸入空間的分散;它在權重裡散得多開要另外量。
- **網路**:2-64-64-1(4,417 個權重),用 torch 訓練。205 個權重的小網路做不出 4 塊以上的缺陷
  (缺陷區錯不乾淨、區外也被弄壞),16 塊要寬度 64 加上較長的微調才成立。
- **修法**:no_edit、llm(查詢預算 0 與 400 個點)、random_edit(同數量,20 次平均)、
  sparse_ft(微調後只留變動最大的 n 個)、dense_ft(全部微調,上限)。
- **prompt 不透露缺陷的位置與塊數**,各 k 用同一段說明。
- **已知弱點**:
  - 規則 x+y>0 很容易重建,LLM 可能是「覆寫出一條新路徑」而不是「修掉錯的地方」;所以另外記改動數與
    最大改動值,之後要換成重建成本高的規則(circle)對照。
  - sparse_ft / min_sparse 取的是微調後變動最大的前 n 個,不是最佳的 n 個。實測連 k=1 都要上千個才修好,
    而 LLM 在小網路上兩個權重就修好同類缺陷,可見這個基準太弱,還不能拿來當「權重空間分散度」。
  - 查詢是單點輸出;400 個點足以定位邊長 0.25 的方塊,但預算與 k 之間的關係還沒掃。

### 試跑結果(k=1 與 k=16 各一個網路,n=1,只能當方向感)
| k | 查詢 | 缺陷區 | 其餘 | 改動數 | 最大改動值 |
|---|---|---|---|---|---|
| 1 | 0 | 0.01 → 0.62 | 0.99 | 10 | 0(把單元歸零) |
| 1 | 400 | 0.01 → 1.00 | 1.00 | 3 | 10000 |
| 16 | 0 | 0.11 → 0.34 | 0.91 | 1 | 15.5 |
| 16 | 400 | 0.11 → 1.00 | 1.00 | 6 | 1000 |

- **有查詢時 LLM 不是在修,是在覆寫**:它挑一個幾乎沒作用的單元,改成 sign(x+y) 偵測器,再用 200–10000 的
  權重壓過網路其餘部分。LLM 自己也寫明這是繞道、不是最小修正。所以 k 再大結果都會是 1.00,這條曲線沒有意義。
- **沒查詢時才看得到分散度的影響**(0.62 對 0.34),但各只有一個網路。
- 單次修改的花費 US$0.26–1.60,四組共 US$3.68;完整掃一輪(4 個 k × 2 個種子 × 2 種預算)估 US$15–25。
- **要讓「修」有意義,下一版必須擋掉覆寫**:目標函數不能是一句話就能重建的規則(改用隨機教師網路的輸出當
  正確答案,只能靠查詢得知),並限制改動幅度(新值不得超出該層原有權重的範圍)。
