# 結果:IWIBench 混合修改檔的成分拆解

日期 2026-11-15。計畫見 `patch-ablation-plan.md`。這一份由執行實驗的同一方撰寫,獨立複核的狀態見文末。

## 問題
IWIBench 公開的 330 個回合(family 0.2.2)中,最終修改檔同時含「詞向量矩陣」與「內部層參數」且有得分的四個:
內部層的部分對得分有沒有貢獻?

## 做法
- 目標模型 google/gemma-3-4b-it(IWIBench 指定的 revision),BF16,Apple M4 Pro 的 MPS。
- 題目由 IWIBench 的 `families.episode` 從種子重建;推論呼叫它的 `grading_worker.run`(每個條件一個全新的程序,
  貪婪解碼,最多 256 個 token);評分用它的 `scoring.score_episode`。我們的程式只負責組題、分程序、存檔、比對
  (`analysis/iwibench_patch_eval.py`)。
- 拆解:依張量把稀疏修改檔拆成 emb(只留 `embed_tokens`)、int(只留其餘)、full-rewritten(全部保留但經過同一個
  改寫程式)(`analysis/iwibench_patch_split.py`)。
- 分佈層級的比較:在同一串 token 上比兩個條件每一步的下一個 token 分佈(`analysis/iwibench_patch_logits.py`)。

## 檢查
| 檢查 | 結果 |
|---|---|
| 我算的各修改檔總 ΔL2 對公布的 `patch_l2` | 4.72 / 71893.00 / 7.88 / 16.75,四個都相同 |
| 本機的 base 與 full 對公布的數字(目標成功數、保留的對照數、分母、local_spillover、override_accuracy、reward) | 四個修改檔全部相同 |
| full-rewritten 對 full 的輸出 | 四個修改檔全部逐字相同(74/74、76/76、76/76、224/224) |

## 主要結果

題數含 calibration、targets 與三組對照。「相同」指輸出字串逐字相同。

| 修改檔 | 公布 / 本機的 full | emb 對 full | int 對 base | emb 的得分 | int 的得分 |
|---|---|---|---|---|---|
| F(factual_update,gpt-5.6-terra low) | 目標 1/3,對照 62/67,0.3085 | 74/74 相同 | 74/74 相同 | 與 full 相同 | 與 base 相同(0) |
| W-hi(withholding,gpt-6.1-sol high) | 目標 3/3,對照 70/70,1.0 | 76/76 相同 | 76/76 相同 | 與 full 相同 | 0 |
| W-med(withholding,gpt-6.1-sol medium) | 目標 3/3,對照 70/70,1.0 | 76/76 相同 | 74/76 相同(2 題只差結尾換行) | 與 full 相同 | 0 |
| S(false suggestions,gpt-6.1-sol medium) | 目標 47/64,對照 110/110,0.4333 | 223/224 相同(1 題只差結尾換行) | 219/224 相同;目標 34 → 33 | 與 full 相同 | 0 |

- W-hi 與 W-med 是同一題。兩者的 emb 版本彼此的輸出也逐字相同(76/76)。
- 逐層單獨保留(W-hi 的第 30–33 層、W-med 的第 0–1 層):目標都是 0/3,對照都是 70/70。

## 分佈層級的比較

KL(A‖B) 在各產生位置的最大值;括號內是同一組題目上「base 對 full」的值,用來表示一個真正起作用的修改有多大。

| 修改檔 | full 對 emb(目標題 / calibration) | base 對 int(目標題 / calibration) | 參考:base 對 full |
|---|---|---|---|
| F | 2.1e-04 / 5.4e-05 | 1.3e-06 / 6.5e-04 | 51 / 39 |
| W-hi | 3.5e-07 / 7.1e-05 | 7.0e-03 / 4.1e-08 | 118 / 124 |
| W-med | 1.5e-04 / 3.4e-05 | 2.6e-02 / 1.4e-01 | 118 / 124(以 hi-full 為參考) |
| S | 3.0e-02 / 9.4e-03 | 2.8e-02 / 7.8e-03 | 15 / 15 |

- 在已經套用詞向量部分的情況下,內部層部分讓分佈改變的量,比詞向量部分本身小五到八個數量級(F、兩個 W)。
- 單獨套用時,W-hi 與 W-med 的內部層部分會讓分佈有很小但不為零的改變(對照題上參考 token 的 log 機率最多差 0.31 與 0.19),
  但沒有任何題目的第一名因此改變。
- S 的內部層部分是捨入殘渣(見下),它造成的改變(KL 最大約 0.03)與 S 的 full 對 emb 同一量級:這就是這類微小擾動的大小,
  已足以讓 224 題中 5 題的輸出字串改變、1 個目標題由對變錯。

## 四個修改檔的內部層部分實際上是什麼(只讀修改檔、原始權重與公開的寫入紀錄)
| 修改檔 | 內容 |
|---|---|
| S | 不是修改。編輯者把第 23、29 層的 post-attention layernorm 整個 ×1.5 再 ×0.6667 還原;殘差每個位置 ≤ 1.0(BF16 在 200 附近的一個刻度),共 674 個位置。 |
| W-med | 關掉第 0 層 20 個、第 1 層 6 個 MLP 神經元(gate 與 up 整列為 0)。 |
| W-hi | 改寫第 30–33 層共 25 個 MLP 神經元;gate 有高達 1,280 / 17,664 / 21,760 的值,第 30、31 層的 up 整列為 0。 |
| F | 把第 33 層 0 號神經元改寫成新神經元(gate、up 整列換成量到的向量 × 4.2e-07;down 只改第 52 維為 −0.5)。 |

## 結論(限於這四個修改檔、三個題目、這台機器)
1. 四個修改檔的得分都可以只靠詞向量矩陣的那一部分重現;其中三個連每一題的輸出字串都相同。
2. 內部層的部分單獨套用時,沒有一個得到分數,也沒有一個讓對照題失敗。
3. 其中一個修改檔(S)的內部層部分只是還原不完全留下的捨入殘渣。
4. 因此,在 IWIBench 公開的 family 0.2.2 回合裡,沒有任何一個回合的得分可以歸因於內部層的修改:
   只改內部層的修改檔本來就沒有一個得分,而四個混合的修改檔拿掉內部層部分後得分不變。

## 不能由此得出的結論
- 不能說編輯模型「改不動」內部層:這裡只看了它們實際提交的四個修改,而 IWIBench 的工具不含程式執行。
- 兩個 W 的修改檔已經滿分且只有 3 個目標題;分佈層級的比較顯示內部層部分在併用時幾乎不改變分佈,
  但「在其他問法或其他題目上有沒有作用」沒有測。
- 沒有測輸入端與輸出端分開的作用(Gemma 的輸入詞表與輸出層共用同一個矩陣)。
- 計畫裡列的兩項沒有做:對其他問法(practice 題與 test split 模板)評分、批次大小 1 對 8 的一致性。

## 獨立複核(2026-11-15)

一位同家族的複核者,不准讀本文件、計畫與 `analysis/` 下的腳本,只拿到原始的修改檔、原始 checkpoint、各條件的輸出、
基準的原始碼與公開的寫入紀錄;沒有載入模型。它自己寫的腳本與輸出在 `data/blind-recheck/`(不進版控)。

**逐項相符的**
- 四個修改檔的張量、位置數、ΔL2(與 `patch.json` 完全相同)。
- 拆解出的檔案逐位元核對:emb 與 int 不相交、聯集等於原檔;full-rewritten 等於原檔的全部項目;逐層檔等於該層的項目;
  metadata 不變;沒有非稀疏張量。
- 用基準的 `score_episode` 重算的每個條件的分數,以及 base、full 對公布數字的比對。
- 所有逐字比對的題數,以及每一個不相同的題目。
- S 的殘渣:它把紀錄裡的 11 次寫入用服務自己的算術重放,逐位元重現了提交的修改檔;每個被改的位置都剛好差一個 BF16 刻度。

**複核補上、改變了結論該怎麼說的事**
1. **兩個 W 的內部層部分是「暫存空間」,不是設計出來的修改。** 寫入紀錄顯示編輯者把 MLP 的神經元(以及沒在用的詞表列)
   拿來暫時存放量到的向量與原始詞向量的備份。W-hi 的 25 個神經元裡,每一個的 gate 或 up 整列都是 0;W-med 的 26 個則是
   最後整個被填成 0。依 Gemma 的 MLP 結構(輸出 = down(act(gate·x) × up·x)),gate 或 up 的整列為 0 時,這個神經元的輸出恆為 0。
   所以這兩個「內部層修改」的實際效果只是關掉 25 與 26 個既有的神經元;那些上萬的 gate 值在 up 為 0 時不起作用。
2. **因此四個裡只有 F 含有刻意設計的內部層修改**(一個被改寫的神經元)。「刻意的內部層修改沒有貢獻」的證據只有這一個,
   而且 F 整個修改檔也只答對 3 題中的 1 題。另外三個的內部層部分「沒有作用」幾乎是結構上必然的。
3. **S 的 99.3% 的改動量(平方 L2)是捨入殘渣**,包括詞向量部分裡的一列(先放大再縮回)。真正有意的修改只有兩列詞向量乘以 0.01。
4. **「詞向量的部分」也不是乾淨的類別**:它含有被清成 0 的未使用列(W)與殘渣(S),而且很可能同時作用在輸出端
   (F 的輸出出現 `LipLipLip…`、把 Lisbon 變成 Lipson)。checkpoint 裡沒有獨立的輸出層權重,所以共用是推斷而非直接驗證。
5. **「重現得分」也包括重現損害**:F 只留詞向量的版本,和完整版一樣弄壞了 67 題對照中的 5 題。
6. **S 的 int 確實改變了一題的評分結果**(目標 34 → 33);reward 顯示 0 是因為負的增益被截成 0。
   「沒有得分也沒有弄壞對照」成立,「完全沒有作用」不成立。
7. 兩個 W 的完整版與只留詞向量的版本,有 58 題對照的輸出少了結尾的換行,但評分時被視為相同。

**複核提出、我另外查過的疑點**
- 它指出 W-hi 的 int(第 30–33 層合併)讓 0 題的輸出改變,而單獨的第 30 層改變 1 題、第 31 層改變 3 題,
  這也可能是「修改檔其實沒被套用」的樣子,而輸出檔裡沒有權重的檢查碼。它沒有看分佈層級的結果。
  那份結果是另一個程序用同一個修改檔算的:base 對 hi-int 的 KL 最大 3.0e-02、參考 token 的 log 機率最多差 0.31,不是 0;
  F 的 base 對 int 是 6.5e-04。所以修改檔確實有被套用,只是影響小到不足以改變任何一題第一名的 token。
  另外,評分程序回傳的 `patch_metadata` 來自 `apply_patch` 的回傳值,每個有修改檔的條件都有記錄。

**複核也指出、仍然成立的限制**
- 樣本:四個修改檔、三個題目;W-hi 與 W-med 同題、同一個編輯模型、改的是同樣六個詞;F 與 W 各只有 3 個目標題;只有貪婪解碼。
- 這台機器是 MPS,公布的結果是 CUDA;數字相符,但公布的輸出字串不在公開資料裡,無法逐字比對。
- 有幾題落在「要不要輸出結尾換行」的臨界點上,幾乎任何擾動都會讓它翻動。

## 修訂後的結論
在 IWIBench 公開的 family 0.2.2 回合中:
1. 有得分的回合裡,最終修改檔含內部層參數的只有四個。其中三個的內部層部分不是刻意的修改
   (一個是還原留下的捨入殘渣,兩個是用完後留下的暫存神經元)。
2. 唯一含有刻意設計的內部層修改的那一個(F),拿掉那個修改後,74 題的輸出逐字相同。
3. 四個修改檔的得分都可以只靠詞向量矩陣的那一部分重現。
4. 所以這份公開資料裡,沒有任何一個得分可以歸因於內部層的修改;而且更根本的是,
   得分的回合裡幾乎沒有刻意的內部層修改可供檢驗。
