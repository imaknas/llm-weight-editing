# 計畫:編輯者端的條件會不會改變「改哪裡」(2026-11-15,第 1 版,待冷審)

## 1. 問題
IWIBench 公開的 330 個回合裡,沒有任何分數可歸因於內部層的修改(`docs/patch-ablation-results.md`)。
我們自己用同一套服務端工具跑的三個 factual_update 回合,編輯者三次都改內部層的 MLP 並得到 0.667,
但編輯者端的條件與基準差很多(模型不同、沒有回應長度上限、可長時間推理、有顧問工具、指示不同)。

要回答的問題:**在服務端完全相同的前提下,「編輯者改詞向量還是內部層」取決於模型,還是取決於編輯者端的生成條件?**

## 2. 已知(不需要花錢重做的部分)
- 基準的設定:null harness、最多 64 輪或 128 次工具呼叫、每次回應 max_tokens 4096、temperature 0、reasoning_effort none(部分模型 low)。
- 原作者已經用 gpt-6.1-sol 跑過 reasoning medium 與 high(仍是 max_tokens 4096):30 個回合的輸出合計 14.2 萬與 31.5 萬 token
  (平均每回合約 4.7k 與 10.5k),factual_update 的三題仍然全部只改詞向量,分數 0.30–0.667。
  所以「只調高推理強度」已經被做過,結果是沒有改變。**沒有被測過的是每次回應的長度上限(以及因此被限制的總思考量)。**
- 我們放寬條件的三個回合每回合輸出 8.6 萬–11.3 萬 token,單次回應最長 4.4 萬。

## 3. 設計
服務端:`analysis/iwi_rpc_server.py`(IWIBench 的 Service,MPS)。題目:factual_update seed 2、0、3。
編輯者端由一個新的驅動程式直接呼叫供應商的 API,提示與工具定義取自基準的 `taskset.py`
(一句任務說明 + 公開資訊的 JSON;四個工具的 schema 與說明逐字取自原始碼),沒有 system prompt,
停止條件與基準相同(64 輪、128 次工具呼叫、或模型給出不含工具呼叫的回覆)。沒有顧問、沒有其他工具。

| 代號 | 模型 | 生成條件 | 回合數 | 目的 |
|---|---|---|---|---|
| S-base | gpt-6.1-sol | max_tokens 4096、temperature 0、reasoning low(公布的 6.1-sol (low) 設定) | 3 題 × 2 | 重現公布的行為(只改詞向量、0.30–0.667),確認我們的服務、MPS、驅動程式沒有改變行為 |
| S-wide | gpt-6.1-sol | 回應上限 32,000、reasoning high,其餘相同 | 3 題 × 3 | 只放寬回應上限(與公布的 sol-high 相比),看會不會改內部層 |
| F-base | claude-fable-5-2 | max_tokens 4096、temperature 0、不開 thinking | 3 題 × 3 | 我們的模型被限制在基準條件時還會不會改內部層 |
| F-wide | claude-fable-5-2 | 回應上限 32,000、開 thinking、其餘相同 | 1 題 × 1(seed 2;有餘額再加) | 沒有顧問、用基準原提示時,先前的結果能不能重現 |

每個回合結束後:用服務評分;patch 用 `iwibench_patch_split.py` 拆成詞向量部分與內部層部分,各自重評(`iwibench_patch_eval.py`)。

**主要觀察量**(每回合):最終 patch 動了哪些張量;分數;拆解後分數來自哪一部分;輸出 token 總量與單次回應的最大值;是否碰到回應上限(finish reason)。

## 4. 事先寫下的讀法
- **S-base 不重現**(例如分數全 0,或改的位置與公布的不同類):先停。表示服務、MPS 或驅動程式與基準有差異,後面的比較都不成立。
  重現的標準:6 個回合中至少 4 個的最終 patch 只含詞向量,且至少 2 個有分。
- **S-wide 有回合靠內部層得分**(拆解確認):回應上限是關鍵之一;公布的「只改詞向量」至少部分是 4,096 上限造成的。
- **S-wide 仍然只改詞向量**:對 Sol 而言回應上限不是原因;差別更可能在模型。
- **F-base 仍然靠內部層得分**:我們的模型不需要大量思考也會這樣做 → 模型的差別。
- **F-base 退回詞向量或 0 分**:思考量對這個模型是必要的。要再看 finish reason:若多數回應撞到 4,096 上限而被截斷,是「被截斷」而不是「選擇不同」。
- **F-wide 不重現先前結果**:先前的結果可能依賴顧問或我整理的指示。
- 組合讀法:S-wide 變、F-base 變 → 條件是主因;S-wide 不變、F-base 不變 → 模型是主因;一變一不變 → 兩者都有,或交互作用。
- 每格只有 3–9 個回合,任何「會 / 不會」都只是這個樣本裡的觀察;不做顯著性檢定,只報計數。

## 5. 花費與停損
- 單價(動用前對照官方價目頁):gpt-6.1-sol 每百萬 token 輸入 2、快取 0.10、輸出 10 美元;claude-fable-5-2 輸入 8、快取讀 0.80、快取寫 10、輸出 40。
- 預估:S-base 6 × 0.3 = 2;S-wide 9 × 2.2 = 20;F-base 9 × 1.8 = 16;F-wide 1 × 12 = 12;合計約 50 美元,上限 60。
- 驅動程式用 API 回傳的 usage 逐次記帳,寫入 `data/api-runs/ledger.jsonl`;每次呼叫前檢查累計,超過上限就不送出。
- 第一個付費回合(S-base)先看快取命中率;命中率低於 50% 就停下來查原因。
- 單一回合的花費超過預估的 3 倍就中止該回合。

## 6. 已知的限制(跑之前就知道)
- MPS 不是 CUDA;S-base 的重現是對這一點的檢查,但只能檢查到「行為類似」。
- 驅動程式不是基準用的 verifiers 框架;工具 schema 的包裝方式(單一 `request` 參數)照原始碼的函式簽名做,但無法確認與框架送給模型的 JSON 完全相同。
- 公布的 sol-high 是對照之一,但它是原作者在 CUDA 上跑的,不是我們跑的。
- 兩個模型對「reasoning」的實作不同(OpenAI 的 reasoning effort 與 Anthropic 的 thinking),「放寬」不是同一種操作。
- 題目只有 factual_update 的三題(同一種事實:職位 → 人名)。
- 服務每 30 分鐘要重啟並接回一次;接回對編輯者不可見(驅動程式等服務回來再重送同一個請求)。
